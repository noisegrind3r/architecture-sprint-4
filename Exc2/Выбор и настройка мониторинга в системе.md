Выбор и настройка мониторинга в системе

1. Мотивация
  Мониторинг необходим для того, чтобы узнавать о проблемах до того, как о них напишет клиент и для того, чтобы определить узкие места в системе (например, нехватка ресурсов, большое количество запросов и т.д.) и спланировать дальнейшие действия исходя из полученных данных.
  Также, использование метрик позволит понять как именно пользователи используют нашу систему и позволит доработать функционал так, чтобы пользователям было удобнее (например, пользователи не пользуются каки-то функционалом, потому что не понимают как).
 
2. Выбор подхода к мониторингу
  Для мониторинга API обеих систем предлагается использовать подход "4 золотых сигнала". Использование данного подхода позволит получить следующие метрики:
  - задержка - позволит оценить скорость отклика системы
  - трафик - позволит оценить количество запросов в секунду
  - ошибки - позволит оценить количество запросов с ошибкой
  - насыщенность - позволит оценить процент загруженности нашей системы

  Для мониторинга баз данных, файлового хранилища и брокера сообщений предлагается использование подхода "USE". Использование данного подхода позволит получить следующие оценки:
  - утилизация - позволит оценить процент загрузки процессорного времени и памяти, которое потребляет сервисы
  - насыщенность - позволит оценить количество ожидающих запросов или длину очереди в брокере сообщений
  - ошибки - количество ошибок при выполнении запросов

3. Список метрик
  Для оценки API системы MES и CRM предлагается использовать следующие метрики:
  - Number of requests (RPS) for MES API, 
    Number of requests (RPS) for CRM API, 
    Number of requests (RPS) for internet shop API - позволят оценить количество запросов в секунду к методу API, ярлыки: метод API
  - Number of HTTP 500 for CRM API, 
    Number of HTTP 500 for MES API, 
    Number of HTTP 500 for shop API - позволят определить количество необработанных ошибок на сервисах и запланировать их устранение, ярлыки: метод API
  - Response time (latency) for CRM API, 
    Response time (latency) for shop API, 
    Response time (latency) for MES API - позволят определить время ожидания ответа от API и принять меры для оптимизации запросов или масштабировании, ярлыки: метод API

  Для оценки БД:
  - Memory Utilisation for shop db instance, 
    Memory Utilisation for MES db instance - позволят оценить нагрузку на память сервера БД и в дальнейшем принять решение о добавлении памяти, масштабировании или экономии ресурсов 
  - CPU Utilisation for shop db instance, 
    CPU Utilisation for MES db instance - позволят оценить нагрузку на процессор сервера БД и в дальнейшем принять решение о добавлении частоты или ядер, масштабировании или экономии ресурсов 
  - Size of shop db instance, 
    Size of MES db instance - позволят вовремя среагировать на нехватку места и устранить проблему до её возникновения
  - Number of connections for shop db instance, 
    Number of connections for MES db instance - позволят оценить количество соединений к инстансу БД и принять необходимые меры в случае превышения лимита соединений

  Для оценки брокера сообщений:
  - Number of dead-letter-exchange letters in RabbitMQ - позволит оценить количество недоставленных сообщений, ярлыки: exchange, routing key
  - Number of message in flight in RabbitMQ - позволит оценить количество ещё не обработанных сообщений в очереди сообщений, ярлыки: queue

  Для оценки хранилища файлов
  - Size of S3 storage - позволит оценить размер S3 хранилища и принять меры к расширению или ограничению, в случае превышения квот, ярлыки: bucket
