Планирование: анализ, идентификация проблем и поиск решений

1. Существующие и потенциальные проблемные места:
  - слишком долгая обработка заказов, проблема не на стороне производства
  - проблема с обработкой заказов усугубилась после открытия собственного API
  - долго загружается стартовая страница MES системы, даже после добавления пагинации и фильтров
  - система MES слишком долго рассчитывает стоимость заказа
  - поиск и исправление ошибок очень трудоёмок и занимает много времени
  - информация о проблемах с быстродействием и заказами приходит от клиентов, а не диагностируются внутри компании
  - сервисы Shop API и CRM API имеют одну базу данных, которая может испытывать большую нагрузку и проблему с dead lock
  - отсутствие мониторинга, логирования и трассировки
  - отсутствие горизонтального масштабирования 
  - деплой в prod окружение вручную может приводить к лишним ошибкам

2. Список инициатив, которые необходимы для устранения нежелательных ситуаций в порядке приоритета (чем выше в списке, тем выше приоритет):
  - добавление мониторинга для оперативной реакции на проблемы
  - добавление логирования и трассировки с целью ускорения поиска проблем 
  - внедрение кэширования для часто запрашиваемы данных
  - добавление API Gateway для балансировки входящего траффика, маршрутизации, лимита запросов
  - после определения узких мест, горизонтальное масштабирование проблемных сервисов
  - устранение проблем скорости расчета стоимости в MES-системе 
  - автоматизация деплоя в prod окружение
  - автоматизация регрессионного тестирования поможет быстрее проводить релиз и уменьшит количество ошибок  
  - разделение БД в сервисах Shop API и CRM API может решить часть проблем с быстродействием
  - разделение команды на 2 подкоманды, занимающиеся MES и CRM, и найм дополнительных сотрудников позволит ускорить релизы и быстрее решить имеющиеся проблемы

3. Целевая архитектура через полгода:
  - добавлен мониторинг, логирование и трассировка, что позволит найти проблемные участки и, если не устранить, то разработать более детальное решение проблем
  - добавлено кэширование для статусов заказов в MES, что позволит устранить проблему с медленной загрузкой стартовой страницы
  - большая часть часто используемого функционала должна быть покрыта авто-тестами, для чего потребуется найм QA-инженера, специализирующего на автоматизации или обучение существующего специалиста
  - добавлен API-Gateway и реализовано горизонтальное масштабирование для MES системы, что позволит увеличить скорость расчета стоимости и обработки заказов
  - найдена проблема в MES-системе с долгим расчетом стоимости заказа и принято решения для её устранения, для чего, возможно, потребуется найм дополнительных c# и React разработчиков
  - деплой полностью автоматический во все среды

4. Основные три пункта из списка инициатив в ближайшие полгода:
  - мониторинг, логирование и трассировка
  - кэширование для статусов заказов в MES
  - добавлен API-Gateway и реализовано горизонтальное масштабирование для MES системы
